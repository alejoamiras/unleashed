## Goal

Replace the eighteen hand-rolled `node:child_process` calls in `packages/bridge-core/scripts/` with ONE argv-only process primitive whose contract is explicit (no shell string anywhere; throw-with-exit-code-and-stderr by default with `check: false` opt-out; secret-safe failure diagnostics; one binary-resolution rule), keep the domain helpers (`runForge`, `buildForkInL1Root`) on top of it, delete the two duplicated `forgeBin()`s and the raw `cast()`/`execSync` variants, un-pin the hardcoded `cast` path, close the target-program injection holes on the git and forge/cast inputs — with the primitive proven by real-subprocess tests on both engines and the scripts' observable behaviour proven preserved by a static per-site audit plus the key-free `verify-l1 --dry-run` run before and after. The e2e supervisor is out of scope (the e2e configs stay on Node). `--no-orphans` is NOT enabled anywhere; the arc records the controlled probe that would clear it.

**Done** = `run.ts` + `run.test.ts`; all six child-process files use it; `rg -n 'node:child_process|execSync|execFileSync|spawnSync' packages/bridge-core/scripts/*.ts` matches only `run.ts`; `bun run --cwd packages/bridge-core typecheck` + `test` green, and `run.test.ts` green under BOTH explicit engine invocations (`bun run --cwd packages/bridge-core vitest run scripts/run.test.ts` — Node by the bin's shebang — and `bun run --cwd packages/bridge-core --bun vitest run scripts/run.test.ts` — Bun), whatever the package `test` script is; `bun run test:all` + `bun run lint` green; `verify-l1 --dry-run` prints exactly its Phase 0 baseline for BOTH manifests (testnet: four ✓ lines; mainnet: the circle-proxy skip line + three ✓) before and after; every script's exit codes, soft-fail paths, accepted inputs and messages preserved except the three documented targeted fixes (no feature or input shape is removed); PR to the base branch open with the three required checks green at HEAD; codex loop converged.

## Why this tier (Phase 0.5 rubric)

Novelty LOW (a process primitive), blast radius LOW–MED (operator-run deploy/verify/canary scripts — never in CI — but they move real funds on Sepolia/mainnet when an operator runs them, so a behaviour change is expensive to discover), irreversibility LOW (revert one PR), migration cost LOW, external coupling MED (forge/cast from the Aztec/Foundry toolchains), security MED (three shell strings interpolate unvalidated input; the deployer key is in the process env AND in `cast` argv). One MED-HIGH-ish dimension, single package → `light`.

| Q2 | Primitive contract | `run(bin, args, opts): RunResult` over `spawnSync` — argv only (never `shell`), `encoding: "utf8"`; options are PER CALL with Node's defaults otherwise (`cwd`, `env`, `stdio`, `maxBuffer` — 64 MiB only where the forge sites already set it; no global stdin/maxBuffer change; no `timeoutMs`). ## Recon → design (see [recon.md](recon.md))

- 18 call sites, 6 files, 4 file-scoped helpers (2 duplicated), 0 tests, 0 CI invocations; the scripts are the `aztec-update` operator runbook.
- Two patterns: A — argv arrays (cast/forge/bun sub-scripts; already shell-free), B — `execSync` shell strings for git (three of them interpolate unvalidated input).
- No shared primitive exists anywhere in the repo. For the deploy scripts the primitive IS the risky part; it gets the tests. Reuse: `candidateManifestSchema`/`parseCandidateManifest` (`src/candidate-schema.ts`) for the forge inputs; `requireAddress()` (`live-intent.ts:97-102`) for the cast inputs; the `git()` error-message shape of `test-soak/cli.ts`.

## Architecture & Implementation

1. **`packages/bridge-core/scripts/run.ts`** (new, ~90 lines, imports nothing local — no cycle by construction):
   - `export class RunError extends Error { readonly bin: string; readonly argc: number; readonly exitCode: number | null; readonly signal: NodeJS.Signals | null; readonly stdout: string; readonly stderr: string; readonly code?: string }` — message as in Q2; no argv and no raw spawn error anywhere on the object (`code` is the spawn error's `code` string, e.g. `ENOENT`).
   - `export function run(bin, args: readonly string[], opts?: { cwd?; env?; stdio?; maxBuffer?; check?: boolean }): RunResult` — `spawnSync(bin, [...args], { ...opts-without-check, encoding: "utf8" })` inside a `try` whose `catch` yields `{ code: "EINVAL-ARG" }`-shaped failure with the fixed reason `invalid argument` (nothing from the thrown error is retained); `shell` is not an option; `res.error` → `RunError` (code only), `res.signal` → `RunError`, `res.status !== 0` → `RunError`, unless `check === false` (then the caller gets `{ exitCode: res.status, signal: res.signal, stdout, stderr, code?: res.error?.code }` — the raw error object is never returned either).
   - `export function resolveBin(name: string, opts: { envVar: string; candidates: readonly string[]; prefer: "path" | "candidates" }): string` — `process.env[envVar]` wins verbatim; then the `prefer`-controlled order: `prefer: "path"` = PATH probe (`run(name, ["--version"], { check: false, stdio: "ignore" })` exit 0 → the bare `name`) THEN the first candidate that `existsSync`; `prefer: "candidates"` = the first existing candidate THEN the PATH probe; nothing resolves → throw `"<name> not found — set <envVar>, install it on PATH, or provide one of: <candidates>"`. Forge: `resolveBin("forge", { envVar: "FORGE_BIN", candidates: [~/.aztec/current/bin/forge], prefer: "path" })` = today's order (env → PATH → `~/.aztec/current/bin/forge`). Cast: `resolveBin("cast", { envVar: "CAST_BIN", candidates: [~/.aztec/current/internal-bin/cast, ~/.aztec/versions/5.0.0/internal-bin/cast], prefer: "candidates" })` = Q8's order. Both existing orders are expressible without branching in the callers. **Resolution is lazy**: `forgeBin()`/`castBin()` resolve on first use and memoize — never at module evaluation — so `fuel-testnet.ts`, `fpc-dust-canary-mainnet.ts` and `smoke-existing-mainnet.ts`, which import only `live-intent.ts`'s signer constants, never require `cast` to exist (today's `CAST` constant is a path string, also inert until used).
   - `export function git(args: readonly string[], cwd: string): string` — `run("git", args, { cwd }).stdout.trim()`; eight sites.
2. **Call-site migration, one commit per file** (order: `portal-artifact.ts` → `verify-l1.ts` → `live-intent.ts` → `restore-swap.ts` → `deploy-bridge-testnet.ts` → `deploy-bridge-mainnet.ts`), each preserving exit codes, the soft-fail branches (`check: false` + the existing ⚠ log), `stdio: "inherit"` where output streams to the operator, the `FOUNDRY_PROFILE`-stripped env and `maxBuffer` 64 MiB on the forge sites, and message texts. Injection-closing forms (git 2.53 verified): `restore-swap.ts:97` → `const oid = git(["rev-parse", "--verify", "--end-of-options", `${fromRef}^{commit}`], repoRoot)` then `git(["show", "--end-of-options", `${oid}:apps/faucet/public/testnet-bridge.json`], repoRoot)`; `live-intent.ts:316` → `intent.source.commit` checked against `/^[0-9a-f]{40}$/` then `["diff", "--name-only", "--end-of-options", oid, "HEAD", "--"]`; `live-intent.ts:290` → `["--literal-pathspecs", "status", "--porcelain", "--", intentPath]`; the static `rev-parse HEAD` / full-tree `status` / fixed `show HEAD:path` need no separator. Deletions: both `forgeBin()`s, `cast()`, the raw `spawnSync`/`execSync`/`execFileSync` imports.

## Security & Adversarial Considerations

- **Target-program (argument) injection**: closed per site — git via `--end-of-options`/`--`/`--literal-pathspecs` on the sites that take variable input; forge via the strict manifest schema (`evmAddress` regex, enums, int chain id); cast via `requireAddress` on every address argument and a shape check on the key. The primitive never interprets a string as a command.
- **Secrets**: `PRIVATE_KEY` reaches `cast` as argv (pre-existing; visible in `ps` on the operator host) — unchanged here, owner Ask A3 (`cast wallet` keystores are the alternative). New guarantee: the primitive never formats or retains argv (message, fields, stack, `cause`, synchronous throws). Outside it, documented: argv is visible in `ps` while a child runs (`PRIVATE_KEY`, `ETHERSCAN_API_KEY`); child-owned output stays verbatim; the inherited environment is the operator's.
- **Supply chain**: no new dependency; no workflow change; no `bun.lock` change.
- **Blast radius**: operator scripts moving real value — behaviour preservation is the gate; one commit per file for bisectable revert.
- **Multi-agent host**: nothing spawns long-lived children or kills by name; `--no-orphans` stays off.
