## Gotchas

- `?raw` SVG imports work under the faucet's jsdom vitest (unlike `.css`), so the sprite keys derive at module init from the same file the sheet renders.
- `parseAmount` in `lib/format.ts` truncates and returns `0n` on junk — useless for a field; `parseAmountStrict` returns `null` and `toDecimalString` renders MAX.
- The first integration run had `SendWizard.test.ts` asserting object identity on a route object and a stale-selection expectation that leaked across tests — fixed on the shell side, not by loosening the components.
- `bun run --cwd apps/faucet test:e2e` went red the moment `useWalletConnection` imported the v2 reader (module-init strict parse of a v1 file); it turns green with the manifest flip in the retire step — the reason the retire step is one commit, not a series.

## Arc-4 quality loop

### Reviewer pass (fresh-context Opus, medium) — 18 findings, no blockers, all acted upon

The ones that mattered: **an exit on a `portal-only` token** (L1 registration exists, hub never bound it) passed `exitTokenBlock`, had no L2 ceiling and, on the private path, no simulate — a burn authwit against a token the hub cannot burn, a reverted tx, a stuck provisional record. Now an exit requires the HUB binding (`ExitTokenNotRegisteredError`, before any authwit), the wizard gates the plan on it and the Amount step renders the reason, and the private preflight builds its off-chain witness first and simulates with it (simulating `exit_to_l1_private` without the witness fails on the missing witness, not on the exit — every private exit would have broken). **The review truncated amounts to two decimals** (0.005 USDC rendered as "0.00" on the screen the user signs, while the receipt's "review said" used full precision) — `toDecimalString` everywhere an amount is about to be signed. **`portalVerified` was a boolean** that rendered "will be created" for both an unreadable chain and a non-zero portal that DISAGREED with the CREATE2 prediction — four states now; a mismatch warns and blocks confirm. The public send ran `ensurePermit2Approval` with an empty record id (an unexplained `approve` in the wallet, a junk `runtime[""]`) — the provisional record now opens before the approval on both paths and re-keys onto the claim hash; `setRecordStep("")` throws. `validateTokenBlock` — the gate for every resumed claim, exit consume and backup import — had no direct test (8 cases now). The requested-token set grew without bound while the wallet truncates its grant at 256 (an unbreakable re-prompt loop past ~251 browsed tokens): LRU of 32 browsed + pinned journal tokens, `forgetHubToken`. A panel's own `retryCapabilities()` owning the flow read as "declined" (the wallet declined nothing): `retryCapabilities(): Promise<boolean>`, outcome `busy`. `readSendReceiptLeaves`'s `{ intent } as SendParams` left `amount` undefined so a receipt-only gas recovery could journal `received: "0"` — `MissingBridgeAmountError`. A11y: focus followed nothing on a step change (keyboard users dropped to `<body>` three times per send), the privacy switch had no accessible name, invalid inputs carried no `aria-invalid`/`aria-describedby`, the list's arrows moved focus but not selection; the sprite adopter now allowlists elements and strips `on*`/`href`. ### Codex pass (xhigh, adversarial) — session `01a064e8-6687-7560-9039-1209f2e4a5bf`

Round 1 verdict: "Do not ship yet: two ordinary user paths are blockers — private fueled deposits strand after L1, and public exits fail before authorization." 14 findings, 13 acted on:

- **Blocker — private `token+gas` never wrote its fuel block.** A private token leg knows its record id before the signature, so `persistPreTx`'s "rewrite when the id changed" branch never ran and the fuel material (`bridgeSecretSalt`, secret, hash) never reached the record — the private fee ladder stopped forever after L1 funds moved. Private gas-only stored the salt but sealed no envelope, so `resolvePrivateSecret` refused it and export was unavailable. Both paths now persist the complete fuel block before the approval and seal every private fueled envelope; the unit tests run the real seal/unseal.
- **Blocker — the public exit simulated before its authwit existed.** `preflightHubExit` ran `exit_to_l1_public` (which burns via `burn_public`) before `set_authorized`, so the Token refused it as unauthorized and every public exit was refused — hidden by tests and the smoke stubbing the preflight. The sandbox had the order right (authwit → simulate → send); the app now matches it, and the tests fake the hub's simulate so it only passes after the authwit tx.
- Should-fix: `performExit` re-checks the exact grant before any authwit; both lanes read the live `eth_chainId` before the signature/burn and again before L1 finalization (an attached RPC on another chain could supply false portal/pause state); a relayer finalizing first (`callerOnL1` is zero) is completion, not a retry loop (Outbox consumption is read back); the sponsored-plus-standalone ladder's standalone Fee Juice claim is launched and journaled; pins are derived from the live journal (discard/clear unpin); the local journal is deep-validated at load with invalid entries quarantined, not crashing boot nor reaching `requestHubToken`; the wallet's capability answer is intersected with the request per scope (an extra contract is ignored, a missing scope is not a grant, `"*"` is empty); a poisoned list cannot label an address — live metadata wins, a conflict warns, list rows and the review show the checksummed address, display strings are control-filtered and capped; a quote clears synchronously and is keyed by its token/probe, and the reviewed plan is a frozen snapshot (any change returns to the Amount step, saying why); the wizard adopts exactly the record id the flow resolves to, never "the first new record"; a backup file over 1 MiB is refused before it is read.
- Rejected (repo policy): "restore MAX's native tab stop" — in-field secondary controls are `tabindex="-1"` by the owner-accepted keyboard rule.

Codex "looks fine": claims cannot be redirected by altering recipient/token/portal fields (chain binding + recipient-derived private secrets fail closed); hostile ERC-20 event spoofing is stopped by emitter filtering; selection epochs and in-app account-switch gating hold; no HTML sink; remote `logoURI` unused; CSP appropriately narrow.
