# Adversarial review of the router strawman

Tags [H/M/L]. Sources: lifinance/contracts `main`, files read in full: `src/Facets/GenericSwapFacetV3.sol` (GSF), `src/Libraries/LibAllowList.sol`, `src/Periphery/{ReceiverStargateV2,Permit2Proxy,Patcher,Executor}.sol`; across-protocol/contracts `master` `contracts/libraries/PeripherySigningLib.sol` (PSL). `SpokePoolPeriphery.sol` 404'd at that path (unverified; PSL holds the type strings). LayerZero, Aztec, Uniswap: not fetched, from memory, marked.

## Verdict

Sound only with three changes: (1) pin the swap call to the two `swapTokens*V3ERC20ToERC20` selectors with `_receiver == router` decoded on-chain ("no allowlist" fails, 2.11); (2) drop "exactly fuelSlice" and "holds zero" (both break on benign behaviour, section 4); (3) the CLIENT must verify the destination params (2.2): on the Across/Executor path nothing on Ethereum knows the user's intent.

## 1. LI.FI source facts

1. GSF swap leg [H]: `_depositAndSwapERC20Single` / `_executeSwaps` require `LibAllowList.contractSelectorIsAllowed(callTo, selector)`; `approveTo != callTo` needs an approve-only entry. That guards the INNER DEX call, not which Diamond function we call.
2. Pull [H]: `LibAsset.transferFromERC20(token, msg.sender, address(this), fromAmount)` (Single) or per `SwapData` with caller-supplied `requiresDeposit` (Multiple; a TODO, EXSC-850, admits unbacked amounts). Consumes our approval to the Diamond. Inside the Diamond `maxApproveERC20` leaves a persistent DEX allowance (Diamond holds nothing between txs).
3. Output [H]: facet-local, whole-balance not delta: `balanceOf(address(this))` of the Diamond checked against `_minAmountOut`, then all of it sent to `_receiver`. Stray AZTEC in the Diamond counts and flows to `_receiver`. Our delta check must be the real floor.
4. Positive slippage [H]: leftover sending asset (> 1 wei) after a non-fee swap goes to `_receiver`; skipped for fee-collection steps (sending == receiving).
5. ReceiverStargateV2 [H]: `lzCompose` is `onlyEndpointV2` and needs `tokenMessaging.assetIds(_from) != 0`. `recoverGas` immutable: if `gasleft() < recoverGas`, skip Executor, transfer `amount` to `receiver`, emit `LiFiTransferRecovered`; else Executor with `gas: gasleft - recoverGas` in try/catch with the same recovery. Forcing it [M, LZ from memory]: EndpointV2's compose execution is permissionless, so anyone submits it with a gas limit just under `recoverGas`+overhead. The recovery returns normally, so the compose is consumed: irreversible downgrade to "bridged asset at the user's address", attacker pays gas only, no theft. Across Receiver has no `recoverGas` (sibling file).
6. Permit2Proxy [H]: (a) EIP-2612 variant: owner = `msg.sender`; `permit()` in try/catch with allowance fallback, so a front-run `permit()` cannot block it, and the proxy only pulls from `msg.sender`, so the observer cannot redirect or steal (the 2612 signature binds no calldata). (b) `callDiamondWithPermit2`: owner = `msg.sender`, no witness. (c) `callDiamondWithPermit2Witness`: owner = caller-supplied `_signer` (anyone may submit); witness `LiFiCall(address diamondAddress,bytes32 diamondCalldataHash)`, type string `"LiFiCall witness)LiFiCall(address diamondAddress,bytes32 diamondCalldataHash)TokenPermissions(address token,uint256 amount)"`. A front-runner can only run the exact signed call at their chosen time; `msg.value` is unbound. It leaves a max-style Diamond allowance.
7. Patcher [H]: `depositAndExecute*` pull the caller's ENTIRE `balanceOf`, approve target max; its docs warn of theft and unrecoverable excess. Precedent against unbounded `balanceOf(msg.sender)` pulls. Not deployed on the testnets.
8. Executor [H]: both entry points public, `nonReentrant`, pull from `msg.sender` only (allowance, or `erc20Proxy.transferFrom(msg.sender)`); forward only post-minus-start deltas of the sent token and last receiving asset (pre-existing Executor balances are never forwarded).

## 2. Attacks on the strawman

1. Threat model [H]: on the Executor path the attacker is whoever authored the Across `message` (compromised LI.FI API / MITM), not a relayer: the relay hash commits to the message.
2. Client must verify before signing the source tx [H as requirement]: tx `to` and the USDC approval spender are the known Diamond (deployments file, not API); selector is `startBridgeTokensViaAcrossV4`/`swapAndStart...`; `receiverAddress` = the known ReceiverAcrossV4; `refundAddress` = the user; `minAmount` = approved amount; `fillDeadline`/`quoteTimestamp` sane; `outputAmount` within a client bound of input (no on-chain tie, sibling file). Decode `message` = `(txId, SwapData[], receiver)`: `receiver` = user's Ethereum address; one `SwapData`, `callTo == approveTo == router`, sending == receiving == token, `fromAmount == outputAmount`; decode `bridgeFromCaller`: secret hashes equal ones derived from the user's own secret (a wrong hash makes the Aztec claim attacker-owned: top severity), Aztec recipient, token portal, `fuelSlice`, `minFuelOutput`, `minReceived == maxPull == outputAmount`, nested swap target = Diamond, allowed selector, `_receiver == router`, `_minAmountOut == minFuelOutput`. Simulate; show fuel amount and recipient.
3. Hostile tokens [H]: token set must be registered bridged tokens plus immutable AZTEC; an arbitrary token lies in `balanceOf` and re-enters. The Diamond hands control to arbitrary pools mid-call, so reentry is real: transient `nonReentrant`, and approve portals only AFTER the swap.
4. Fee-on-transfer / blacklist [H]: USDC is upgradable/blacklistable: measure arrivals by delta, require `>= minReceived`, deposit measured amounts not `intent.amount`. A blacklisted `receiver` also breaks the Receiver's recovery transfer, so the fill reverts and Across refunds at expiry.
5. Donations [H]: anyone can send token/AZTEC to the router. A `balanceOf == 0` assert is a permanent DoS lever; equality checks break if a donation lands mid-swap. Snapshot after the pull, use deltas, leave donations stranded.
6. Executor's standing MAX approval [H]: the Executor max-approves `approveTo` (our router) and never resets; third parties cannot exploit it (router pulls only from `msg.sender`). But the Executor is permissionless: an attacker runs `swapAndExecute` with `callTo = router`, and `balanceOf(Executor)` includes any stray Executor balance, which an unbounded `maxPull` sweeps into the attacker's intent. Fix: `maxPull == amount`.
7. `maxPull` [H]: Across fills equal `outputAmount` exactly, so client sets `minReceived = maxPull = outputAmount`; Stargate `amountLD` may differ slightly, hence the pair.
8. Low destination gas (Across) [M]: SpokePool calls `handleV3AcrossMessage` directly, Receiver has no `recoverGas`. If the inner call OOGs, the Receiver keeps R/64 for recovery (~50k) so R >= ~3.2M, when the inner call already had far more than needed: a relayer cannot cheaply force OOG-then-recover; too little gas reverts the whole fill and the relayer eats it. Rule: no try/catch or tolerated failure in the router, so a 63/64 starve can never skip an optional step. Slow-fill is permissionless: same analysis. Stargate differs (1.5).
9. Staleness / sandwich on the ~$7k AZTEC/WETH 1% pool [M]: Bitget leg expires (revert, safe); OKX has no deadline but a fixed `minReturn`; the delta floor is the only price protection. A sandwich pays the 1% fee twice, so unprofitable at tens-of-dollars slices unless tolerance > ~2%: keep client tolerance <= ~1% (not measured; fork-test it). A pump past the floor reverts (safe, fuel+deposit fail to route). No trustworthy on-chain oracle exists at this TVL.
10. Permit2 front-run / nonce [H]: owner = `msg.sender` means no stranger can submit or burn the nonce. With a `_signer` design a front-runner executes only the exact signed intent at their timing. Random unordered nonces, short deadline, one-time USDC approval to Permit2.
11. "No selector allowlist" [H it is unsound]: deltas cap loss at `fuelSlice` (exact approval), but `callTo = Diamond` exposes every facet function with the router as `msg.sender`, and the only fuel-side constraint is `minFuelOutput`, which the message author sets. Counter-example: `startBridgeTokensViaAcrossV4` (or any `startBridgeTokensVia*`) with `minAmount = fuelSlice`, receiver = attacker, `minFuelOutput = 0`: token delta == fuelSlice, fee-asset delta >= 0, approvals zeroed, every check passes, the slice is bridged to the attacker. The Diamond's owner also cuts facets in and out, so the surface changes under us. The argument holds only if `minFuelOutput` is client-verified; the allowlist removes that dependence (two immutable selectors + reading `_receiver` at its ABI head offset).
12. Compromised facet [M]: loss capped at `fuelSlice` if nothing else is approved, plain `call` only, order pull -> swap -> check -> approve portals. It can still return the minimum AZTEC and pocket the price gap; accepted trust in LI.FI.
13. Native ETH [H]: Across gives wrapped token only; Stargate native `value` into a non-payable router reverts, the Executor's `try` fails, user gets ETH at their address. Safe, not a feature.
14. First-time `createPortal` [M]: gas cliff (+~350k, sibling) and a race: must be get-or-create or an attacker pre-creating the clone reverts every first user into recovery (grief, no loss). Deposit only to portals the hub registered.
15. Decoy deposits [L, Aztec semantics from memory]: public hash, but claim needs the secret; decoys cost the attacker funds. Real risk is indexers matching by hash alone: match by tx hash/transactionId plus amount.
16. Atomicity [H]: any revert unwinds both deposits; the LI.FI Receiver then sends the full amount to `receiver` (sibling file). No refund logic needed in the router.

## 3. Witness precedents

- Across swap-and-bridge (PSL) [H]: type string `"SwapAndDepositData witness)"` + `BaseDepositData(address inputToken,bytes32 outputToken,uint256 outputAmount,address depositor,bytes32 recipient,uint256 destinationChainId,bytes32 exclusiveRelayer,uint32 quoteTimestamp,uint32 fillDeadline,uint32 exclusivityParameter,bytes message)` + `Fees(uint256 amount,address recipient)` + `SwapAndDepositData(Fees submissionFees,BaseDepositData depositData,address swapToken,address exchange,uint8 transferType,uint256 swapTokenAmount,uint256 minExpectedInputTokenAmount,bytes routerCalldata,bool enableProportionalAdjustment,address spokePool,uint256 nonce)` + `TokenPermissions(address token,uint256 amount)`; referenced types appended alphabetically. `message` and `routerCalldata` bound as `keccak256`; binds exchange, min output, spokePool, every deposit field. Deadline: Permit2's own (the non-Permit2 paths wrap `SignedSwapAndDepositData(..., uint256 deadline)` so a submitter cannot swap the deadline).
- LI.FI Permit2Proxy [H]: only diamond address + `keccak256(diamondCalldata)`.
- Pattern: bind every field, hash all `bytes`, name the executing target, bind the minimum output; Permit2 binds deadline, nonce, spender, token and amount.

Recommended witness `RouterDeposit(bytes32 aztecRecipient,bytes32 secretHash,bytes32 fuelSecretHash,address tokenPortal,uint256 fuelSlice,uint256 minFuelOutput,address swapTarget,bytes32 swapDataHash)` + `TokenPermissions` (alphabetical: `RouterDeposit witness)RouterDeposit(...)TokenPermissions(address token,uint256 amount)`). No own nonce or deadline; require `requestedAmount == permitted.amount`.

## 4. Ranked invariants and test layers

1. Funds leave only to the token portal, FeeJuicePortal, or the Diamond (`<= fuelSlice`); router net balance change == 0 modulo donations. Stateful invariant + halmos.
2. `pulled <= min(maxPull, allowance, balanceOf(caller))`, only from `msg.sender`/Permit2 owner; stray caller funds untouched when `maxPull == amount`. Fuzz + invariant.
3. Token delta in `[0, fuelSlice]`, fee-asset delta `>= minFuelOutput > 0`. Strawman "exactly" is wrong (positive slippage returns part of the slice, which belongs in the deposit). Fuzz with a mock DEX (leftover / more / less AZTEC).
4. Atomicity: every failure reverts everything, no try/catch. Unit, plus a fork test of the real ReceiverAcrossV4 + Executor with a failing router asserting funds land at `receiver`.
5. Allowances to Diamond and both portals are 0 after every call; mid-swap only the Diamond holds `fuelSlice`. Fuzz.
6. Reentrancy from a hostile token/DEX reverts. Unit with adversarial mocks.
7. Selector/receiver pinning (2.11): random selectors rejected; `_receiver == router`; `_minAmountOut >= minFuelOutput`. Unit + fuzz.
8. Witness completeness: mutating any intent field or one byte of `swapData` invalidates the signature; foreign `msg.sender` and replay revert. Fuzz + fork against real Permit2.
9. Donation robustness (pre/mid-call) never reverts or mis-deposits. Invariant with a donor actor.
10. Idempotent get-or-create portal; deposit only to registered portals. Fork with the real factory.
11. Real-bytecode fork: Sepolia Receiver + Executor + Diamond with a live AZTEC route; mainnet-fork sandwich at slice size to test 2.9.

Strawman fixes: (a) "exactly fuelSlice" -> `<=`, deposit the measured remainder; (b) "holds zero" -> deltas only; (c) `min(balanceOf, maxPull)` OK only with client `maxPull == amount`; (d) add the two-selector allowlist and pin `_receiver`; (e) `minFuelOutput` non-zero and client-verified; (f) get-or-create portal.
