# Follow-ups

Open work lifted out of closed plans, one entry each; delete an entry when it resolves.

- **A Cloudflare account of its own for unleashed.** The build token the three Workers share has Workers Scripts Edit on the whole account, so it could overwrite the owner's other Workers there. Per-Worker roles now exist for deploys (Editor on one Worker), but not for custom domains, and creating a Worker still needs account-wide Admin. Accepted as a residual; revisit before the mainnet bridge goes live.
- **Per-Worker build tokens.** Give each Worker's Workers Builds its own token with Editor on that Worker only, now that Cloudflare offers per-Worker roles for deploys: `unleashed-testnet`, `unleashed-mainnet` and `unleashed-landing` share one account-wide token today. A deploy that adds or moves a custom domain would still need the account-wide permission.
- **`AppShell.vue` should import the mark from `@unleashed/design/core/mark.ts`.** The landing reads the mark from there; the app shell still inlines the same path data, and `apps/landing/src/markup.test.ts` pins `MARK_INK` against it. Switch the shell over and delete that pin.
- **A drawn social preview image.** The landing's Open Graph card is `summary`, text only, because no preview image is drawn. Drawing one is a visible change, so it needs the owner's sign-off; then add `og:image` and `twitter:image` and switch to `summary_large_image`.
- **The landing's Bridge copy names Ethereum and Aztec only.** When more source chains ship, the row's line ("between Ethereum and Aztec") is incomplete, though not wrong. Updating it is a visible change, so it needs the owner's sign-off.
- **The tools build trusts any `WORKERS_CI_COMMIT_SHA`.** `apps/tools/vite.config.ts` slices it to 8 characters unchecked, and Workers Builds has put the branch name there (`main`, on the landing Worker's first build after its import), so such a build would ship the id `<version>+main`. Use the landing's `apps/landing/build-commit.ts` rule: the variable only when it is a 40-hex SHA, else `git rev-parse HEAD`, else fail.
- **A backgrounded exit still waiting on the wallet reads as interrupted.** While its `sendTx` is pending, `useHubExit.ts` narrates the provisional exit without marking the journal busy, so its card and dock row say Needs you with "The exit was interrupted…" instead of Running. Mirror that operation's lifetime into the record's runtime; do not infer running from a persisted provisional record alone.
- **Monogram mark contrast.** `token-sprite.ts` stripes a monogram in `hsl(h 55% 42%)`/`32%`; `--ul-on-mark` (#fbf9f3) on it falls to about 2.5:1 at yellow hues. The mark is decorative (`aria-hidden`, and the symbol is printed beside it), but a luminance-based stripe lightness would make it legible at every hue. This is a visible change, so it needs the owner's sign-off.
- **Mainnet SIGNAL/NOISE deploy.** The faucet tokens exist on testnet only; the mainnet build renders the placeholder, so nothing is broken today. Deploying the catalog there (same salts, universal deploys) is a production action: it needs the owner's authorization and the `bridge-generation` runbook's gates.
- **Pixel search icon.** The token search field in `TokenStep.vue` still draws a smooth, stroked magnifying glass beside the pixel icons. Vendoring Pixelarticons' `search` through `bun scripts/vendor-icons.ts` and rendering `<Icon>` would match it. It is a visible change outside the approved icon mapping, so it needs the owner's sign-off.
- **Decode motion.** The design's number scramble on live values was deferred. It needs a JS scramble that lands on the final value, with `aria-live` announcing that value once and reduced motion showing it directly. It is a visible change, so it needs the owner's sign-off.
- **Toasts over controls at short heights.** Desktop toasts sit bottom left, on the page content's edge. Measured with toasts up (`archive/aprime-fidelity/lessons/phase-12.md`), they cover the footer's contract links on short pages, and the amount step's Back below a window height of about 780px. At 761–~800px wide they also cover Continue, Back and "Sign and send".
- **G03 has no automated pin.** The wizard's scoped strip rule once styled `MintStrip`'s root (a child's root carries its parent's scoped attribute), and jsdom does not evaluate styles. A browser assertion on the mint strip's height or fill would pin it.
- **Phone theme control.** At ≤760px the theme control is the labelled cycling button ("System", no fill); the Mobile board draws a 36×36 raised icon button. Hiding the label and adding the fill on phones is small, but visible.
- **The footer at 390** breaks between "Aztec:" and "Bridge hub".
- **v5 testnet records.** The app withholds records from the v5 generation at boot, and that network is gone, so nothing can claim them. Delete this entry unless a user reports a stuck v5 record.
- **A reset mode for `live-intent promote`.** `assertZeroSeed` refuses any identity, factory or hub move against a live manifest, so a reset retires the live manifest by hand first (`bridge-generation` step 7). An explicit mode that allows the move only toward the intent's own identity would remove that manual step.
- **A router-only redeploy forgets the router it replaces.** `routerOnlyCandidate` (`generation-router.ts`) overwrites `depositRouter` without listing the replaced router in `legacyRouters`, so reconcile stops finding that router's in-flight deposits once the candidate is promoted. Carry it over the way `retireRouterCandidate` (`live-intent.ts`) carried the old router, before any second router-only arc.
- **Arc 10 of the A′ inventory, deferred:** G11's stored event log (the in-flight Log panel is session-only today), G39 proof print, G47 sign-on-review, G78 a tooltip primitive, G122 a loading skeleton; G77 is the decode motion above. The gap inventory is in `archive/aprime-fidelity/recon.md`.
- **The conductor's L1 reads need a lag-tolerant readback, and one Inbox writer still sends a bare estimate.** `runSend` and `createPortal` send their estimate plus 25 %, because an Inbox message's gas depends on the bucket state it lands in, and `createPortal` fails a reverted receipt as a revert. `fee-juice-canary-testnet.ts`'s deposit is the other Inbox writer, still on a bare estimate. Separately, `readFactoryBindings` and `ensurePortal` read straight after a receipt, which the keyed Sepolia RPC answered from a lagging backend three times in the `aztec-rc3` deploy; a short retry on those reads would end the manual re-runs.
- **Disabling the old testnet dRPC key breaks `inference-money`'s deployer.** Both old keys stay enabled until the owner disables them (`aztec-rc3`'s A5); warn that repository first. It commits the key in `deployments/testnet.json` and `packages/deployer/src/networks.ts`, so its deployer stops reaching the node once the key is disabled. Stale copies of the key also sit in `unleashed-legacy` and in a standalone copy of the wallet source. Each repository owns its fix; this one edits none of them.
- **`lifi-routing` rebases onto the 6.0.0 line.** Its testnet deploy ran on a network that has since reset, so it is void. Rebase the stack onto 6.0.0 and scrub the two intents it commits with the old testnet key in `primaryRpc`: `node-keys.test.ts` fails on them as they stand. Adopt the per-scope line rule of `aztec-line.test.ts`, then redeploy its router over the 6.0.0 generation's factory (`0x2509…7817`).
- **Set `MIN_FUEL_FJ` from the measured private ceiling.** The manifest's `minFuelFj` floor is the source constant `MIN_FUEL_FJ` in `deploy-generation.ts` (29.773 FJ); `calibrate` writes only `fjPerTx` and `fjRegister`. The `aztec-rc3` live calibration measured a worst private ceiling of 8.516 FJ (the private first claim, registration included) and 2.839 FJ for a plain private claim, so the floor holds a 3.5× margin. The validator's `4× worst getFeeLimit` heuristic says 34.064 FJ. Pick the rule, then set the constant in a source change before a generation: a source edit inside a live window voids its intent. The 6.0.0 generation keeps 29.773 FJ, the owner's choice: lowering the floor is a product call on the fuel margin. Its live calibration measured the same ceilings as rc.3, to the wei.
- **`calibrate` should require a paid plain public claim.** `calibrateFuelBudgets` sizes `fjPerTx` from any paid plain sample, so `aztec-rc3`'s first matrix, which had no plain `claim_public`, passed and under-quoted a public claim by about 18 % until a second promotion fixed it. The runbook now asks for the sample; refusing a matrix without one would make that executable.
- **rc.3 testnet records.** The app withholds records from the rc.3 generation at boot, and the 6.0.0 reset retired that network, so nothing can claim them. There is no migration UI. Delete this entry unless a user reports a stuck rc.3 record.
- **rc.1 testnet records.** The app withholds records from the rc.1 generation at boot, and the rc.1 rollup is no longer canonical, so nothing can claim them. There is no migration UI. Delete this entry unless a user reports a stuck rc.1 record.
- **Mainnet stays on its line until Aztec Alpha upgrades.** The move to rc.3 left mainnet as it was: its operator scripts lost only their literal node key, and `deploy-private-fpc-mainnet.ts`, `deploy-canonical-private-fpc.ts` and `fpc-dust-canary-mainnet.ts` keep the FPC deploy path that the testnet dropped; the mainnet FPC descriptor stays frozen at the FPC it runs. Refresh them, and deploy anything mainnet needs, as an arc of its own when Aztec Alpha upgrades.
- **The mint strip's token mint waits the full receipt budget.** `MintStrip.vue` reads a manifest-token mint's receipt with `awaitL1Receipt`'s defaults through the wallet's provider. A chain switch after signing therefore holds every strip button for up to 8 × 90 s, then shows the bridge journal's "Retry resumes" advice, which does not apply to a mint. The AZTEC mint (`useFeeAssetMint`) already caps the wait at two rounds and names the hash; give the token path the same.
- **`AddressesView.test.ts` times out under heavy load.** Each case runs `vi.resetModules()` and re-imports the view (about 3.3 s for the file alone), so at load average 200+ one case passes the 5 s default timeout. `aztec-fee-asset` hit this on four full runs. A per-file `testTimeout`, or one import shared across cases, would end the re-runs.
- **Rotate the shared dRPC CLI key.** The `aztec-6-stable` live window stashed it, with the other keyed values, in an owner-only tmpfs file for the window's length (the owner's one-time exception), and the stash was dropped at the window's end. Rotate it as on a leak (`AGENTS.md` § Security): disable it in dRPC, mint a new one, replace the 1Password field. This is the owner's step.
- **Bump `zod` to 4.6.6.** `apps/tools` and `bridge-core` declare `zod ^4.4.3`, and the lockfile resolves 4.4.3, which `bun audit` flags for GHSA-mrhx-c7xc-m3w5 (high, memory exhaustion on oversized constrained collections, fixed in 4.6.6). The `@aztec-labs/*` packages, viem's `abitype` and `@nulo-sh/wallet-sdk-schema-patch` reach the same 4.4.3 copy: check that the bumped lockfile leaves no 4.4.3 behind them.
