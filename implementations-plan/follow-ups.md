# Follow-ups

Open work lifted out of closed plans, one entry each; delete an entry when it resolves.

- **A Cloudflare account of its own for unleashed.** The build token the three Workers share has Workers Scripts Edit on the whole account, so it could overwrite the owner's other Workers there. Per-Worker roles now exist for deploys (Editor on one Worker), but not for custom domains, and creating a Worker still needs account-wide Admin. Accepted as a residual; revisit before the mainnet bridge goes live.
- **Per-Worker build tokens.** Give each Worker's Workers Builds its own token with Editor on that Worker only, now that Cloudflare offers per-Worker roles for deploys: `unleashed-testnet`, `unleashed-mainnet` and `unleashed-landing` share one account-wide token today. A deploy that adds or moves a custom domain would still need the account-wide permission.
- **`AppShell.vue` should import the mark from `@unleashed/design/core/mark.ts`.** The landing reads the mark from there; the app shell still inlines the same path data, and `apps/landing/src/markup.test.ts` pins `MARK_INK` against it. Switch the shell over and delete that pin.
- **A drawn social preview image.** The landing's Open Graph card is `summary`, text only, because no preview image is drawn. Drawing one is a visible change, so it needs the owner's sign-off; then add `og:image` and `twitter:image` and switch to `summary_large_image`.
- **The landing's Bridge copy names Ethereum and Aztec only.** When more source chains ship, the row's line ("between Ethereum and Aztec") is incomplete, though not wrong. Updating it is a visible change, so it needs the owner's sign-off.
- **The tools build trusts any `WORKERS_CI_COMMIT_SHA`.** `apps/tools/vite.config.ts` slices it to 8 characters unchecked, and Workers Builds has put the branch name there (`main`, on the landing Worker's first build after its import), so such a build would ship the id `<version>+main`. Use the landing's `apps/landing/build-commit.ts` rule: the variable only when it is a 40-hex SHA, else `git rev-parse HEAD`, else fail.
- **A backgrounded exit still waiting on the wallet reads as interrupted.** While its `sendTx` is pending, `useHubExit.ts` narrates the provisional exit without marking the journal busy, so its card and dock row say Needs you with "The exit was interrupted…" instead of Running. Mirror that operation's lifetime into the record's runtime; do not infer running from a persisted provisional record alone.
- **Monogram mark contrast.** `token-sprite.ts` stripes a monogram in `hsl(h 55% 42%)`/`32%`; `--ul-on-mark` (#fbf9f3) on it falls to about 2.5:1 at yellow hues. The mark is decorative (`aria-hidden`, and the symbol is printed beside it), but a luminance-based stripe lightness would make it legible at every hue. This is a visible change, so it needs the owner's sign-off.

Vendoring Pixelarticons' `search` through `bun scripts/vendor-icons.ts` and rendering `<Icon>` would match it. - **A "deposit requested" marker.** After a reload with a wallet prompt open, a cross-chain card stays "not found yet" with no revoke and no Dismiss, and the exact approval stays open until revoked elsewhere. A journaled marker, with cross-tab care, would let a send never asked for its deposit end safely.

An Arbitrum lost-hash window wider than one run's 2,000-block chunks stays `incomplete`. `deposit-reconcile`'s 50,000-block cap leaves a hash-less Ethereum-origin record older than about 7 days `incomplete`.

- **A stale comment.** `packages/bridge-core/src/journal.ts` says the FPC-address salt is always `Fr.zero()`; the canonical salt is `0x…01` (`private-fpc-canonical.json`).
- **The e2e port resolver can draw a port Chromium refuses.** `apps/tools/scripts/e2e/resolve-ports.ts` picks random ports in the static window without skipping Chromium's restricted list, so a run that draws one (10080 did, on a CI shard) fails every cell at `page.goto` with `net::ERR_UNSAFE_PORT`. - **The conductor's L1 reads need a lag-tolerant readback, and one Inbox writer still sends a bare estimate.** `runSend` and `createPortal` send their estimate plus 25 %, because an Inbox message's gas depends on the bucket state it lands in, and `createPortal` fails a reverted receipt as a revert. `fee-juice-canary-testnet.ts`'s deposit is the other Inbox writer, still on a bare estimate. Separately, `readFactoryBindings` and `ensurePortal` read straight after a receipt, which the keyed Sepolia RPC answered from a lagging backend three times in the `aztec-rc3` deploy; a short retry on those reads would end the manual re-runs.
- **Disabling the old testnet dRPC key breaks `inference-money`'s deployer.** Both old keys stay enabled until the owner disables them (`aztec-rc3`'s A5); warn that repository first. It commits the key in `deployments/testnet.json` and `packages/deployer/src/networks.ts`, so its deployer stops reaching the node once the key is disabled. Stale copies of the key also sit in `unleashed-legacy` and in a standalone copy of the wallet source. Each repository owns its fix; this one edits none of them.
- **Set `MIN_FUEL_FJ` from the measured private ceiling.** The manifest's `minFuelFj` floor is the source constant `MIN_FUEL_FJ` in `deploy-generation.ts` (29.773 FJ); `calibrate` writes only `fjPerTx` and `fjRegister`. The `aztec-rc3` live calibration measured a worst private ceiling of 8.516 FJ (the private first claim, registration included) and 2.839 FJ for a plain private claim, so the floor holds a 3.5× margin. The validator's `4× worst getFeeLimit` heuristic says 34.064 FJ. Pick the rule, then set the constant in a source change before a generation: a source edit inside a live window voids its intent. The 6.0.0 generation keeps 29.773 FJ, the owner's choice: lowering the floor is a product call on the fuel margin. Its live calibration measured the same ceilings as rc.3, to the wei.
- **`calibrate` should require a paid plain public claim.** `calibrateFuelBudgets` sizes `fjPerTx` from any paid plain sample, so `aztec-rc3`'s first matrix, which had no plain `claim_public`, passed and under-quoted a public claim by about 18 % until a second promotion fixed it. The runbook now asks for the sample; refusing a matrix without one would make that executable.
