# Follow-ups

Open work lifted out of closed plans, one entry each; delete an entry when it resolves.

- **A Cloudflare account of its own for unleashed.** Workers Scripts:Edit cannot be scoped to one Worker, so a build token for this repository could overwrite the owner's other Workers on the same account. Accepted as a residual; revisit before the mainnet bridge goes live.
- **A backgrounded exit still waiting on the wallet reads as interrupted.** While its `sendTx` is pending, `useHubExit.ts` narrates the provisional exit without marking the journal busy, so its card and dock row say Needs you with "The exit was interrupted…" instead of Running. Mirror that operation's lifetime into the record's runtime; do not infer running from a persisted provisional record alone.
- **Monogram mark contrast.** `token-sprite.ts` stripes a monogram in `hsl(h 55% 42%)`/`32%`; `--ul-on-mark` (#fbf9f3) on it falls to about 2.5:1 at yellow hues. The mark is decorative (`aria-hidden`, and the symbol is printed beside it), but a luminance-based stripe lightness would make it legible at every hue. This is a visible change, so it needs the owner's sign-off.
- **Mainnet SIGNAL/NOISE deploy.** The faucet tokens exist on testnet only; the mainnet build renders the placeholder, so nothing is broken today. Deploying the catalog there (same salts, universal deploys) is a production action: it needs the owner's authorization and the `bridge-generation` runbook's gates.
- **Pixel search icon.** The token search field in `TokenStep.vue` still draws a smooth, stroked magnifying glass beside the pixel icons. Vendoring Pixelarticons' `search` through `bun scripts/vendor-icons.ts` and rendering `<Icon>` would match it. It is a visible change outside the approved icon mapping, so it needs the owner's sign-off.
- **Decode motion.** The design's number scramble on live values was deferred. It needs a JS scramble that lands on the final value, with `aria-live` announcing that value once and reduced motion showing it directly. It is a visible change, so it needs the owner's sign-off.
- **Toasts over controls at short heights.** Desktop toasts sit bottom left, on the page content's edge. Measured with toasts up (`archive/aprime-fidelity/lessons/phase-12.md`), they cover the footer's contract links on short pages, and the amount step's Back below a window height of about 780px. At 761–~800px wide they also cover Continue, Back and "Sign and send".
- **G03 has no automated pin.** The wizard's scoped strip rule once styled `MintStrip`'s root (a child's root carries its parent's scoped attribute), and jsdom does not evaluate styles. A browser assertion on the mint strip's height or fill would pin it.
- **Phone theme control.** At ≤760px the theme control is the labelled cycling button ("System", no fill); the Mobile board draws a 36×36 raised icon button. Hiding the label and adding the fill on phones is small, but visible.
- **The footer at 390** breaks between "Aztec:" and "Bridge hub".
- **Mainnet on the v6 line.** Mainnet still runs the older line, so the mainnet operator scripts and the mainnet FPC descriptor were left as they were when the testnet moved to 6.0.0-rc.1. Refresh them, and deploy anything mainnet needs, as an arc of its own when Aztec Alpha upgrades.
- **Aztec 6.0.0 final.** The testnet runs 6.0.0-rc.1. Final will probably reset the network or move class ids, which means a second generation through the `bridge-generation` runbook.
- **v5 testnet records.** The app withholds records from the v5 generation at boot, and that network is gone, so nothing can claim them. Delete this entry unless a user reports a stuck v5 record.
- **A reset mode for `live-intent promote`.** `assertZeroSeed` refuses any identity, factory or hub move against a live manifest, so a reset retires the live manifest by hand first (`bridge-generation` step 7). An explicit mode that allows the move only toward the intent's own identity would remove that manual step.
- **A router-only redeploy forgets the router it replaces.** `routerOnlyCandidate` (`generation-router.ts`) overwrites `depositRouter` without listing the replaced router in `legacyRouters`, so reconcile stops finding that router's in-flight deposits once the candidate is promoted. List the replaced router at the front of `legacyRouters` before any second router-only arc; the router-only scope already refuses a candidate that drops a listed one.
- **Arc 10 of the A′ inventory, deferred:** G11's stored event log (the in-flight Log panel is session-only today), G39 proof print, G47 sign-on-review, G78 a tooltip primitive, G122 a loading skeleton; G77 is the decode motion above. The gap inventory is in `archive/aprime-fidelity/recon.md`.
- **`ensurePortal` ignores the receipt's status.** It waits for `createPortal`'s receipt and then reads the registration, so an out-of-gas revert surfaces only as "landed but the factory has no registration". Check `status`, and pad the gas estimate: one `createPortal` was given 306974 gas and ran out, where an identical call one block earlier had used 345130.
- **Size `minFuelFj` with a full calibration.** The private first claim's measured ceiling is 14.88 FJ against the 29.77 FJ floor, a 2.0× margin where the validator sizes the floor to 4× (59.5 FJ). One sample cannot move the floor. Pre-create a fresh token unregistered, run `PUBLIC_RUNS=0 fuel-testnet --token <it>` with `PRIVATE_RUNS` unset (three private runs, the first of them the private first claim; the public lane would register the token first) and a `FUEL_SLICE_UNITS` that clears the floor, then set it.
