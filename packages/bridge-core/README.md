# @unleashed/bridge-core

The private side of the bridge, beside the protocol and flows in [`@unleashed/sdk`](../sdk/README.md): the app's
journal, backups and seals, the token list, the cross-chain source leg and its discovery, the deploy, verify and
canary scripts, and the sandbox. No React, no Vue, no server. The proven reference for every flow is
`scripts/deploy-sandbox.ts --smoke`.

One **generation** per network: an L1 `PortalFactory` (one storage-less portal clone per ERC-20) and
one L2 `TokenBridgeHub` that registers a token from the factory's attested words and derives its L2
`Token`, with a `DepositRouter` and its swap target bound to the factory. Every DERIVABLE address (portal, hub, L2 token) is a pure function
of that tuple and the SDK re-derives it rather than trusting a file; the factory, router and swap
target are deployed addresses the verifier cross-reads instead.

| `promotion.ts` / `relay-claim.ts` | The promotion interlock, relayer-claim primitives. |

## Key invariants

- **Secrets persisted before the irreversible L1 tx.** A lost claim salt/secret strands funds — the journal record (with its sealed fuel salt for every private fueled shape) is written before the signature is requested. **A PRIVATE claim is recipient-committed.** The stored `secret` for a private deposit is a per-deposit `claim_salt`; `claim_private` re-derives the consumption secret from `(claim_salt, recipient)` in-circuit (`deriveTokenClaimSecret` ↔ the Noir `claim_secret` lib, keystone-pinned), so a leaked salt only lets someone claim to the ORIGINALLY-BOUND recipient — a relayer can finish the deposit, never redirect it. Integrators MUST still seal the salt at rest and NEVER log/URL/plaintext-persist it: losing it strands the deposit (sole recovery input), and leaking it reveals the recipient↔amount↔leaf linkage. **Two salt rules, distinct risks:** (1) *keep it secret* — a LEAKED salt → the linkage above; (2) *keep it full-entropy-random* (64 WebCrypto bytes reduced into the field, `randomField()`; never deterministic): the private deposit's `secret_hash` is public on L1, and the salt alone keeps the recipient out of it. Pinned by `claim-secret.test.ts`. The **public** path stays a raw secret (`claim_public` binds the recipient in its content hash).
- **Tests run under vitest, not `bun:test`.** `@aztec-labs/foundation` calls `expect.addEqualityTesters` at import, which `bun:test`'s `expect` lacks — any test that (transitively) imports `Fr`/`AztecAddress` throws at import. Always `import { … } from "vitest"`. (The vitest suite executes on the Bun *runtime* — `bun --bun vitest run` — which is a different thing.)
- **Scripts spawn other programs ONLY through `scripts/run.ts`** — argv arrays, never a shell string (`run(bin, args)` throws `RunError` on any failure; `resolveBin` finds `forge`/`cast` by one rule: `FORGE_BIN`/`CAST_BIN` override, then PATH or the Aztec toolchain folders). Argv closes shell injection, not a hostile flag: values that reach `git`/`forge`/`cast` are validated first.
- **The conductor's journal is the recovery.** Every irreversible deploy step is appended after its receipt, stamped with the chain/rollup/deployer identity; a re-run skips journalled steps and never re-derives the factory or hub. Both are additionally adopted from chain when they landed before their line was written (the two with cross-bindings); the swapper and router are adopted only from their own journalled step — a crash between landing and the append deploys that one contract again, so read the journal against the chain before re-running. Never edit it, and never delete it while its generation may still be resumed: a completed generation's journal is retired, in its own commit, when the next generation starts on the same network (`bridge-generation`).
